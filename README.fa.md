# 🎵 اسمارت میوزیک تِگِر

### پاکسازی و تغییر نامِ خودکارِ متادیتای موسیقی با هوش مصنوعی.

[English](README.md) | **فارسی**

---

اسمارت میوزیک تِگِر نام فایل‌های موسیقی شما را با هوش مصنوعی تحلیل می‌کند،
متادیتای دقیق را استخراج می‌کند، تگ‌های تمیز را در فایل می‌نویسد و آن‌ها را
به قالبی یکدست تغییر نام می‌دهد — به‌صورت خودکار، روی کل پوشه‌ها.

این برنامه با **دو رابط کاربری قابل‌تعویض** ارائه می‌شود که از یک موتور
هسته‌ای مشترک استفاده می‌کنند:

- 💻 **خط فرمان (CLI)** — رابط ترمینال که با فایل `.env` کار می‌کند
- 🌐 **رابط وب (GUI)** — اپلیکیشن Flask با نمایش زندهٔ پیشرفت

خروجی هر دو کاملاً یکسان است. بسته به نیازتان یکی را انتخاب کنید.

---

## ✨ امکانات

- **استخراج متادیتای هوش مصنوعی** با Groq API (با راستی‌آزمایی از طریق جستجوی وب)
- **تگ‌های تمیز** — متادیتای مزخوب موجود را پاک کرده و فقط فیلدهای راستی‌آزمایی‌شده را می‌نویسد
- **تغییر نام خودکار** فایل‌ها به `Artist - Song.ext`
- **دو رابط کاربری** — CLI برای اتوماسیون، رابط وب برای اجرای تعاملی
- **نمایش زندهٔ پیشرفت** — رابط وب پیشرفتِ هر فایل را از طریق Server-Sent Events نشان می‌دهد
- **لاگ‌گیری دقیق** — هر اجرا یک فایل لاگ قابل‌خواندن تولید می‌کند
- **معماری ماژولار** — منطق هسته کاملاً از رابط کاربری جدا است
- پشتیبانی از **MP3، FLAC، WAV، M4A، OGG**

## 📦 نصب

### پیش‌نیازها

- **پایتون ۳.۸ به بالا**
- **pip**
- یک **کلید Groq API** — به‌صورت رایگان از <https://console.groq.com/keys> بسازید

### مراحل

۱. **مخزن را کلون کنید**
   ```bash
   git clone https://github.com/parsasafaie/smart-music-tagger.git
   cd smart-music-tagger
   ```

۲. **نصب وابستگی‌ها**
   ```bash
   pip install -r requirements.txt
   ```

۳. **ساخت فایل پیکربندی**
   ```bash
   cp .env.example .env
   ```

۴. **فایل `.env` را با مقادیر خود پر کنید** (به [پیکربندی](#-پیکربندی) مراجعه کنید):
   ```env
   GROQ_API_KEY=your_groq_api_key
   GROQ_API_URL=https://api.groq.com/openai/v1
   GROQ_MODEL=groq/compound-mini
   GROQ_REQUEST_DELAY_SECONDS=3
   MUSIC_DIRECTORY=C:/Users/YourName/Music
   ```

> ⚠️ **فایل `.env` را محرمانه نگه دارید** — این فایل شامل کلید API شماست و در `.gitignore` قرار دارد.

## 🚀 استفاده

یکی از رابط‌ها را انتخاب کنید. هر دو همان خط لوله را اجرا می‌کنند و نتیجهٔ یکسانی می‌دهند.

| حالت | دستور | مناسب برای |
|------|-------|------------|
| 💻 **خط فرمان (CLI)** | `python cli_main.py` | اتوماسیون، اسکریپت، سرورها، ماشین‌های بدون رابط گرافیکی |
| 🌐 **رابط وب (GUI)** | `python gui_main.py` | اجرای تعاملی، مشاهدهٔ زندهٔ پیشرفت، پردازش دسته‌ای یکباره |

### خط لوله (در هر دو حالت یکسان است)

برای هر فایل صوتی در پوشهٔ موسیقی شما:

۱. 🎯 **تحلیل** نام فایل با هوش مصنوعی ← استخراج متادیتا
۲. 🧹 **پاکسازی** تمام تگ‌های موجود فایل
۳. ✍️ **نوشتن** متادیتای تمیز و راستی‌آزمایی‌شده (عنوان، هنرمند، آلبوم، ژانر، سال…)
۴. 📝 **تغییر نام** فایل به `Artist - Song.ext`
۵. 📒 **ثبت لاگ** نتیجه

### 🌐 حالت رابط وب (Flask)

رابطی مبتنی بر مرورگر که تنظیمات را از یک فرم می‌گیرد و پیشرفت را زنده نشان می‌دهد.

```bash
python gui_main.py
```

سپس **<http://127.0.0.1:5000>** را در مرورگر باز کنید، فرم را پر کنید و روی **Start Tagging** کلیک کنید.

**گزینه‌ها:**

| فلگ | پیش‌فرض | توضیح |
|-----|---------|-------|
| `--host` | `127.0.0.1` | آدرس اتصال (`0.0.0.0` را فقط در شبکهٔ مورداعتماد استفاده کنید) |
| `--port` | `5000` | پورت اتصال |
| `--debug` | خاموش | فعال‌کردن حالت دیباگ/ری‌لود Flask |

> 🔒 **امنیت:** سرور به‌صورت پیش‌فرض روی `127.0.0.1` (فقط همین ماشین) متصل می‌شود.
> کلید API شما فقط برای شروع کار ارسال می‌شود و **هرگز** ذخیره، لاگ یا در هیچ
> پاسخی بازگردانده نمی‌شود. اگر فایل `.env` وجود داشته باشد، فیلدهای غیرمحرمانهٔ
> آن به‌عنوان راحتی در فرم پیش‌پر می‌شوند.

## ⚙️ پیکربندی

تمام تنظیمات در فایل `.env` قرار دارند (CLI از آن استفاده می‌کند؛ رابط وب
همین مقادیر را از فرم خود می‌گیرد).

| متغیر | الزامی | پیش‌فرض | توضیح |
|-------|:------:|---------|-------|
| `GROQ_API_KEY` | ✅ | — | کلید Groq API شما |
| `GROQ_API_URL` | ✅ | — | نقطهٔ پایانی Groq API (`https://api.groq.com/openai/v1`) |
| `GROQ_MODEL` | ✅ | — | نام مدل (`groq/compound-mini`) |
| `GROQ_REQUEST_DELAY_SECONDS` | ❌ | `3` | حداقل فاصلهٔ زمانی میان درخواست‌های API |
| `MUSIC_DIRECTORY` | ✅ | — | مسیر پوشهٔ موسیقی شما |

## 🏷️ متادیتای نوشته‌شده

برای هر فایل، هوش مصنوعی موارد زیر را استخراج و می‌نویسد:

- **نام آهنگ** (عنوان)
- **هنرمند(ها)** — از چند هنرمند پشتیبانی می‌کند
- **آلبوم**
- **ژانر**
- **سال انتشار**
- **هنرمند آلبوم** و **شماره ترک** (در صورت وجود)

هوش مصنوعی نام فایل را با حذف تگ‌های بیت‌ریت (`320kbps`)، نام سایت‌ها/منابع
و برچسب‌هایی مثل «Official Video» یا «Lyrics» پاکسازی می‌کند — سپس متادیتا را
فقط در صورت نیاز و با جستجوی وب راستی‌آزمایی می‌کند و هرگز فیلد ناشناخته‌ای
را حدس نمی‌زند.

## 🏗️ معماری

اسمارت میوزیک تِگِر از یک **طراحی ماژولار و لایه‌ای** استفاده می‌کند. تمام
منطق تجاری در یک سرویس قابل‌استفادهٔ مجدد (`TaggerService`) قرار دارد که هر
دو رابط آن را راه می‌اندازند — در نتیجه CLI و GUI هیچ منطقی را تکرار نمی‌کنند.

```
       cli_main.py                gui_main.py
       (reads .env)               (web form)
            │                         │
            └────────────┬────────────┘
                         ▼
               TaggerService  ← core/service.py
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
    FileScanner     FileProcessor    FileRenamer
                         │
                GroqClient (AI) + MetadataWriter
                         │
                     Logger → log file
```

**اصل کلیدی:** هسته چیزی دربارهٔ CLI یا GUI نمی‌داند. افزودن رابط وب
**بدون هیچ تغییری** در `cli/` یا `core/` انجام شد — این رابط فقط ورودی فرم را
به همان سرویس متصل می‌کند و پیشرفت را از طریق یک callback بازمی‌گرداند.

برای جزئیات کاملِ ماژول‌ها به [`ARCHITECTURE.md`](ARCHITECTURE.md) مراجعه کنید.

### ساختار پروژه

```
smart-music-tagger/
├── cli_main.py             # نقطهٔ ورود خط فرمان
├── gui_main.py             # نقطهٔ ورود رابط وب (Flask)
├── config/
│   └── config_loader.py    # بارگذار .env (CLI)
├── core/                   # منطق تجاری مشترک
│   ├── service.py          # TaggerService — ارکستراسیون
│   ├── scanner.py          # اسکن فایل‌ها
│   ├── processor.py        # تحلیل AI + نوشتن تگ
│   └── renamer.py          # تغییر نام فایل‌ها
├── ai/                     # کلاینت Groq + مدل‌های داده
├── metadata/               # خواندن/نوشتن تگ (mutagen)
├── cli/                    # رابط ترمینال (Rich)
├── gui/                    # اپ وب Flask (پیشرفت SSE)
│   ├── app.py              # ساخت‌کنندهٔ اپ Flask + مسیرها
│   ├── runner.py           # اجرای کار در پس‌زمینه
│   ├── progress.py         # ذخیرهٔ رویداد SSE (نخ‌امن)
│   ├── templates/
│   └── static/
├── logs/                   # فایل‌های لاگ تولیدشده
└── requirements.txt
```

## 📒 لاگ‌گیری

هر اجرا یک فایل لاگ در `logs/music_tagger_YYYYMMDD_HHMMSS.log` می‌نویسد که شامل:

- نام فایل اصلی ← نام جدید
- متادیتای استخراج‌شده
- وضعیت موفقیت/شکست
- هر خطایی که رخ داده است
- خلاصهٔ نهایی پردازش

## 🛠️ رفع اشکال

| مشکل | علت احتمالی و راه‌حل |
|------|----------------------|
| **«Configuration file not found»** | فایل `.env` را بسازید: `cp .env.example .env` |
| **«Missing required configuration»** | تمام کلیدهای الزامی را پر کنید (به [پیکربندی](#-پیکربندی) مراجعه کنید) |
| **«Music directory does not exist»** | مسیر `MUSIC_DIRECTORY` را اصلاح کنید |
| **خطای API `401 Unauthorized`** | `GROQ_API_KEY` نادرست یا نامعتبر است |
| **«No audio files found»** | پوشه فایل MP3/FLAC/WAV/M4A/OGG ندارد |
| **تغییر نام شکست می‌خورد** | دسترسی نوشتن / نام‌های فایل تکراری را بررسی کنید |
| **پورت GUI اشغال است** | با `--port 5001` اجرا کنید |
